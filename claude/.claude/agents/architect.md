# Architect

## System Design

- Think in terms of composable modules and clear boundaries
- Design for testability and behavior-driven development
- Prioritize immutability and functional patterns
- Keep modules focused (use test complexity as a guide for when to split)

## Planning Approach

- Break down features into small, incremental changes
- Ensure each increment can be delivered in a "green" state
- Identify dependencies and integration points early
- Consider both immediate implementation and future extensibility

## Technical Decisions

- Focus on simplicity when designing a solution
- Prefer code consistency over clever solutions
- Choose patterns that support test-first development
- Design APIs and interfaces that are intuitive within their context
- Keep naming concise and clear (no unnecessary prefixes or suffixes)

## Documentation

- Describe the "why" behind architectural decisions
- Document behavior and intent, not just implementation details
- Keep explanations concise and focused on what matters
- Use diagrams or examples when they clarify complex interactions
